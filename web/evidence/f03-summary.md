# F03｜方案與 Claude 審查說明

狀態：待 Claude 外部驗證。這是依既有文件整理的方案摘要，尚未收到本案件的 Claude 回覆。

## 原始問題、限制與交付要求
兩項產品的實際成本高於基準。哪些差異值得優先調查？在不損害品質、安全與交期的條件下，應採取什麼下一步？
交付要求：提出建議方向、理由與假設、替代選項、執行步驟及決策關卡。本案交付是方案，不要求額外實作成品。

## 案件與資料
合成資料，非真實企業營運。來源日期 2026-10-25，整理呈現 2026-11-14。兩項產品、baseline／actual 共四列，幣別依既有示範定義為合成 TWD。資料無日期與期間長度。

## 建議方案（待外部驗證）
先核對資料口徑與工時來源，再依有界驗證結果決定是否小範圍改善。現階段不建議直接全廠改造、採購系統或宣稱 AI 投資必要。
選項：維持監測；先驗證再試點（條件式建議）；直接全面改造（現階段延後）。
假設：工時定義／分攤改變、等待／換線／停機、品質／返工／規格改變、作業組合／記錄錯誤。
需要期間、良品數、工時口徑、規格變更、班次或工單彙總、產能及交期資料。關鍵資料不足就停在補資料，不推進試點。
真實責任人、預算、樣本、改善門檻、品質安全與停止條件確認前，不實施現場變更。
差異不可直接當作可節省額；未知期間不年化、不報 ROI。尚無真實成效。

## 舊紀錄的審查與限制
既有角色演練包含 A01／A02／A06／A08／A15，為同一對話共享上下文。第二組資料曾因缺工時而停止，由 host 補資料後重開，不是自主修復或盲測。
舊模擬審查檢查過：成本差異不等於浪費、工時歸因不等於因果、情境不等於承諾、文件接受不等於實施授權。這不是 Claude 外部驗證。
沒有本研究的新組織版本比較、未見案例驗證或可歸因的能力演化結果。聊天 token 與成本未量測。

## 請 Claude 審查方案
1. 依原始問題、限制與交付要求，判斷方案是否切題、足以支援決策。
2. 檢查推論、假設、證據與取捨，指出未支持的因果、節省、ROI 或實施承諾。
3. 檢查替代方案、執行步驟、驗收與停止條件是否合理，指出缺口及下一步證據需求。
4. 每項發現附位置、嚴重程度、理由與修正要求；無法確認處明示不確定。
5. 數字需核對時，可另附合成 CSV 重算。未提供附件時，不宣稱已核對底層數據；仍可審查方案，並記錄證據限制。
6. 分開判斷客觀檢查、方案品質與實際成效，不把示範或模擬審查當真實驗證。

請保留使用的 Claude 模型、日期、提供材料版本與完整回覆，再更新網站狀態。
