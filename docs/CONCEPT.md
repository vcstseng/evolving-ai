# 概念草案｜The Evolving Firm

日期：2026-11-14。

## 核心
讓 AI 組織處理企業問題，從執行與審查中辨識能力缺口，再透過取得資料、工具、方法、調整分工或建立角色來補足。有效改變保留，並在後續案件驗證能否重用。

核心循環：案件 → 初始方案 → 檢查與審查 → 缺口診斷 → 能力改變 → 重測 → 下一案重用。

## 組織形式
沿用既有 Consulting Agent Framework 的 16 種專業角色規格，按案件選用，不代表本專案已部署或驗證全部角色。

三層責任：專業執行（明確分析模組）、案件整合（組隊、矛盾與交付）、能力發展（跨案件缺口與能力生命週期）。A01 為案件整合起點；A02 與 A15 提供橫向證據與評估支援；能力發展責任另行設計。

Junior／Senior／Manager／Director／Partner 為早期討論的例子，不是固定職級需求。人類保留真實授權與重大取捨。

## 缺口處理
先分辨執行錯誤、資料不足、方法不適、交接失敗、工具缺口與專業缺口。可以重派工、補資料、補工具、修改方法、招募現有角色或建立新角色；允許停止。新增 Agent 不是預設答案。

## Review
Claude 可作外部模型審查者，但不是最終真理。審查需指出位置、理由、證據、修正要求與不確定性。數字與硬性限制另用程式或來源查核。真實成效需要問題擁有者或實施結果支持。

## 題目變化
後續案件、新限制與受約束的合成變體可測試能力邊界。真實案件與合成變體清楚標示。固定保留未參與改進的測試案例。

## 第一版
定位為可行性與質性案例研究。先觀察能否診斷缺口、做出合理改變並有效重用，不宣稱組織架構勝過一般 Agent。候選限制：一個主要案件、少量回測／未見案例、有限改進輪數與能力候選。

## 待決定
首個案件、可用資料、評估規則、模型與工具、預算及執行方式均未確定。

## 長期成功訊號
下一個案件因過往經驗而改善，且能說明重用了什麼、在哪些條件有效、成本是否值得、何時失效。

## 實作狀態
Layer 1 與案件頁已建立，並加入本機半自動交接器及本輪角色契約。外部模型審查串接、獨立多 Agent 執行與研究比較尚未實作。以另一個 Consulting Agent Framework 的 16 種角色為參考，本輪改編 A01/A02/A06/A08 切片，另設 CD 責任。

## 問題與組織的雙版本演化
問題、案件與執行版本分開。問題版本 P1/P2/P3 記錄資料、目標、限制及驗收變化；組織版本 A1/A2/A3 記錄角色、方法、工具與分工變化，實際血脈可分支。

規劃以問題版本 × 組織版本交叉測試：適應（修改後處理變更）、泛化（未針對新案例修改）、能力保留（舊案是否退步）。新一代可能失敗而舊代成功，版本不是能力排名。保留有條件有效的舊版本，記錄重跑穩定性、成本、適用與失效條件，再決定保留、合併或退役；自動版本選用尚未實作。

不同問題目標下的分數不能直接比較。未測不是失敗。首頁矩陣為虛構的 UI 示意，不是實驗資料。

## 案件展示範圍
規劃從 99 Problems 選首批 10 題，尚未選定。首頁以實驗案件、組織與能力、改進紀錄為入口，不重建完整問題庫。依本輪要求，不在首頁加入 Consulting Demo 的站點定位說明。

## 第一輪範圍收斂
先選一種工作與數個案件，追蹤一次可識別的能力改變，檢查它在未見案件是否可重用，以及舊案是否退步。普通 Agent＋相同工具＋記憶與反思為必要探索性對照，保持相同可用資料、模型、工具權限與總預算。小型試行不支持統計優越性結論。

首批 10 題仍為後續範圍規劃，尚未選定。第一輪不要求建立新 Agent，不必同時完成三組組織比較；自動出題、無限制擴編與版本路由留待後續。首頁雙版本矩陣僅展示測試概念。

## Layer 2 案件展示與外部驗證
F03 採用既有合成案例第二組資料作為展示與可核對材料，不是新的演化成果或未見測試。最終 solution 必須交 Claude 驗證；收到真實回覆後保留模型、日期、材料版本、發現與修訂紀錄，才更新審查狀態。歷史共享上下文模擬審查不能替代此步驟。客觀算術檢查、Claude 審查與企業成效維持分開。

## 依問題定義交付
方案本身就是 output。先按問題定義交付要求；策略與營運題可只提出方案，分析與實作題才依需求附計算、資料或成品。Claude 主要依原始問題、限制與交付要求審查方案的切題性、推論、取捨與可行性。附件選用，未取得必要證據時須標示無法確認，不宣稱已核對。案件頁主線為方案 → Claude 審查 → 缺口診斷與修改 → 再驗證；目前已收到轉貼審查，方法修正、重跑與演化驗證仍待執行。

## 內容優先與方案版本
先讓讀者看懂問題與方案，深入後才探索審查、修改、版本與組織。共用可挑戰、保留歷史與容許分支的原則，但此站仍以企業解題為目的，不改成 Blog。

方案版本 v1 與問題版本 P、組織版本 A 分開。2026-11-15 先固定 F03 已發布的題目與方案文件，不吸收同模型模擬審查。固定後不得覆寫，另存新版本並記錄 parent、修改原因、來源審查、分歧與成本（未知須註明）。本次只有 v1，沒有新的能力驗證。

案件列表僅列登錄紀錄，狀態代表目前下一步而非品質分數；待解題、待審查、修改中、待重用測試可篩選，空狀態不補假資料。

## 2026-11-15｜本機執行切片
新增半自動任務交接器：A01 範圍 → A02 證據 → A06 計算 → A08 營運假設 → A01 整合 → CD 缺口診斷。A02/A06 為程式工作，其他角色由同一模型對話協助完成。此流程沒有獨立模型隔離、外部裁判、自主模型調用或新能力驗證。

Claude 是外部驗證者，不是建立與執行流程的前置條件。內部調整決策可先留存；資料取得與能力改進是否成立仍需後續證據。新角色須先成為有契約與資格測試的候選，不能直接稱為已驗證能力。原始角色交付與事件只存本機，公開摘要不包含原始執行紀錄。實作與限制詳 LOCAL_WORKFLOW.md。
