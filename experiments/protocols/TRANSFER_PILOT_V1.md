## 1. 這次只問什麼
固定 Gen 3 的證據閘門，在同類成本分析新案例上，能否比 Gen 2 少做不受支持的判斷，又不增加乾淨案例的誤擋？與普通 Agent 相比，額外流程是否值得？

這是方法在新實例的探索性重用檢查，不驗證企業成效、自主 CD 演化、一般顧問能力或職級組織優越。來源候選是提交 `2549c7894e41eb358b1fd12a8f2d5b7f3441e8da`；若審碼後修改，另存版本並在實驗前重新凍結。

## 2. 三組與唯一主要差異
| 組 | 處理方式 | 控制與解讀 |
|---|---|---|
| A 普通 Agent | 單一 Agent、基礎計算／資料檢查工具、可在自身執行內反思與修訂 | 強基準，不刻意限制成一次回答；可用本次任務記憶，沒有前次答案或跨組紀錄。 |
| B Gen 2 | 固定角色／交接／工具規則，含 no_gap 原機制 | 作為舊方法基線，不拿走它已有的功能。 |
| C Gen 3 | 同一組織切片，加本輪固定原題、引用、可比性及交付閘門 | B→C 是主要方法對照；新增 gate 是處理差異，不能同時開給 A／B 又聲稱在測它。 |

三組共用同一基礎計算器、輸入資料／metadata／來源文字、原題與子問題、模型快照、可用外部權限及總預算上限。A／B 也看到所有宣告與矛盾，沒有藏給 C 的提示。共同最終交付要求為方案＋逐子問題回答／未知＋主張依據／限制；格式映射須在執行前固定，不用 C 的專有欄位名扣 A／B 分。

B→C 仍是一組閘門規則的整體效果，不能拆稱某條規則單獨有效。A→B／C 是實務方案比較，不能由此單獨歸因層級或 Agent 數量。

## 3. 最小規模與隔離
| 案例槽位 | 目的 | 是否可標為未見 |
|---|---|---|
| S1 | 新實例中的口徑衝突 | 未參與修改的新內容；同一問題類型，不稱遠遷移。 |
| S2 | 證據未知，須限制結論或補資料 | 同上。 |
| S3 | 可比性證據充分的乾淨對照 | 同上；必須能支持題目要求，不能只靠「資料有填」。 |
| R1 | 既有產量／順序功能回歸 | 已知公開資料，只算能力保留，不算未見。 |

每題每組兩次獨立執行，共 **4 × 3 × 2＝24 份完整交付**，不是 24 次 API 呼叫。兩次只觀察穩定性，不把同一題重跑當成新增獨立案例。

S1–S3 的內容與答案由與實作／求解隔離的人或模型準備，這輪不建立。出題者提供共同輸入、子問題／主張對應、答案依據與可接受替代回答、重大缺陷及誤擋規則，先封存指紋。方法作者不讀答案、也不依答案修改方法；執行模型各開新上下文。被提前看過的題降級為開發題，另記原因，不偷偷換題。

子問題分解與評分規則要由隔離的問題擁有者確認，不能只採 C 的工具分類當真理。答案雜湊只證明未改，隔離還要靠權限與上下文紀錄；封存答案不進一般公開 Git 或求解輸入。

## 4. 相同上限、停止與成本
- 每份完整交付：最多 8 次求解模型呼叫、輸入 token 總計 40,960、輸出 token 總計 8,192、20 分鐘牆鐘時間；任何一項先到即停止。這是規劃上限，模型／費用未核定前不執行。
- 所有派工、交接、自我反思、格式修復、拒收後重試都計入；不因角色多而加預算。A 可在相同上限內反覆修訂，不強迫用完；B／C 不保證每輪都能完成六步。
- 按供應者口徑記輸入、輸出、快取及可取得的推理 token；快取不重複加到輸入總量。另記總費用與耗時。相同上限不等於實際花費相同。
- 評分模型與人工時間另列為評估成本，不回饋求解方、不混入求解 token；總金額上限須涵蓋求解與評估，開始前核定。沒有可靠用量資料就不能稱等預算實驗或成本勝出。
- 求解失敗、拒收、逾時、用盡預算及缺資料均留在結果分母，不能以「流程沒完成」刪掉。無效輸入可正確停止；關鍵是有沒有清楚標示原題未完成。
- 外部服務故障另記 technical_invalid；由未看答案／分數的管理者判斷，最多整個同題同重複的 A/B/C 區塊重跑一次，原紀錄與費用保留。第二次仍失敗就停止該區塊，不補抽有利結果。
- 實驗期間不給 Claude 審查回饋修答案、不跨題累積新方法、不改規則。需要修程式則停止，保留當前批次，另開研究版本；模型或預算變動也須另版。

## 5. 評分：以原題及答案依據為準，不以 gate 判自己通過
每份交付由同一份事先固定評分表判斷，保留以下分項，不合成加權總分：

| 指標 | 記法與定義 |
|---|---|
| 重大漏檢 | 已種入且有來源支持、會改變所求判斷的缺陷未被指出／限制；逐缺陷記 0/1 及引用位置。只說「可能有問題」不足以命中。 |
| 誤擋 | 答案依據足以支持的子問題，卻無理由拒答或要求不必要資料；逐子問題記 0/1。來源本就未知時的保留不是誤擋。 |
| 原題完整度 | 每個必答子問題分 complete_correct／conditional_partial／incorrect／not_answered，附理由。補資料或機械計算可有價值，但不能代替未回答的判斷。 |
| 不受支持的主張 | 逐項數出把不可比資料當真實率差、把歸因當原因／節省、或聲稱未有的審查／授權；同義重複只算一項，重大者另標。 |
| 數值錯誤 | 在明示計算慣例下核對可重算數值；容許預先訂定的顯示四捨五入。算對條件式金額不代表商業解讀正確。 |
| 成本與狀態 | 實際 token／費用／耗時、拒收／重試／停止、是否有可評交付；不把 no_gap 或完成六步當品質分數。 |

數字以獨立重算核對；語意判斷由不知道組別的外部模型依固定答案評閱，人工覆核重大漏檢／誤擋與分歧。作者可作內部自查，但不能自稱獨立裁判。保留原方案內容，只移除會直接透露組別的標籤；若文字仍讓評分者猜到來源，記錄盲化限制。讀不到材料、未能核對或裁判分歧記 unresolved，不默認通過。

一份交付只有在所有必答子問題 complete_correct、沒有重大漏檢／不受支持主張／數值錯誤，且沒有重大誤擋時，才記「完整且無重大錯誤」。有用的受限交付另列，不硬塞成通過或一律當失敗。全部組別使用同一規則。

## 6. 先寫定怎麼解讀
這 3 個新實例＋1 個已知回歸只支持描述性結果，不做統計優越性或一般化企業主張；逐題逐次配對列 C−B，並同時列 A，不能只報最好一次。

「值得繼續擴大」的預設條件：C 至少在一個新案例的兩次執行都比 B 少重大漏檢，其他案例不增加重大錯誤；乾淨與回歸題兩次皆無重大誤擋／退步；有可比費用時 C 的總求解費用不超過 B 的 1.5 倍。任一不成立或評分未決，不宣稱達標，分開報改善、退步、無差異、成本未知。B 總費用為零／缺值時不算倍率，改報絕對費用且成本條件未決。

這是是否值得再研究的門檻，不是已驗證有效的標準。若 A 品質相當且更便宜，優先考慮普通 Agent；C 只勝 B 不足以支持保留整個組織架構。差異若只來自同字／不同字規則，也只能宣稱這項規則在所測情境的效果。
